# SentinelAI — Database & RLS Specifications

This document specifies the database architecture, schema definitions, and Row-Level Security (RLS) policies for **SentinelAI**.

---

## 🏛️ Database Engine

* **Engine**: PostgreSQL (managed via Supabase)
* **Client Interface**: `@supabase/supabase-js`
* **Resilient Offline Architecture**: Transparent Proxy wrapper (`src/lib/supabase.ts`) auto-switching to an in-memory mock store when remote connection parameters are unconfigured or unreachable.

---

## 📋 Schema Definitions

### 1. `users` Table
Stores registered user identities and security posture metadata.

| Column | Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | `uuid` | Primary Key, References `auth.users(id)` | Unique user account ID |
| `email` | `text` | Unique, Not Null | User email address |
| `full_name` | `text` | Nullable | User display name |
| `avatar_url` | `text` | Nullable | Profile avatar URL |
| `security_posture` | `integer` | Default `92` | Calculated security posture score (0–100) |
| `emergency_contact` | `text` | Nullable | Emergency phone number for high-priority dispatch |
| `created_at` | `timestamptz` | Default `now()` | Account creation timestamp |

---

### 2. `incidents` Table
Stores actionable security incident tickets generated by threat scanners or SOC operators.

| Column | Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | `text` | Primary Key (e.g. `INC-0248`) | Unique incident identifier |
| `title` | `text` | Not Null | Incident summary title |
| `severity` | `text` | Check (`critical`, `high`, `medium`, `low`) | Incident severity level |
| `classification` | `text` | Not Null | Threat type (e.g., Phishing, Vishing, QR Spoof) |
| `risk_score` | `integer` | Range `0–100` | Calculated Fraud Confidence Index |
| `source` | `text` | Not Null | Ingestion vector (WhatsApp, SMS, Call, URL) |
| `status` | `text` | Check (`investigating`, `resolved`, `blocked`, `pending`) | Workflow status |
| `evidence` | `jsonb` | Default `'{}'::jsonb` | Parsed indicators, OCR text, and acoustic signatures |
| `created_at` | `timestamptz` | Default `now()` | Incident detection timestamp |

---

### 3. `security_events` Table
Stores raw threat telemetry events ingested across multi-modal scanners.

| Column | Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | `uuid` | Primary Key, Default `gen_random_uuid()` | Event GUID |
| `event_type` | `text` | Not Null | Telemetry classification |
| `severity` | `text` | Check (`critical`, `high`, `medium`, `low`, `info`) | Event severity |
| `source` | `text` | Not Null | Ingestion origin |
| `risk_score` | `integer` | Range `0–100` | Telemetry risk calculation |
| `metadata` | `jsonb` | Default `'{}'::jsonb` | Parsed structural headers and payload details |
| `timestamp` | `timestamptz` | Default `now()` | Ingestion timestamp |

---

## 🔐 Row-Level Security (RLS) Policies

All tables enforce PostgreSQL Row-Level Security:

```sql
-- Enable RLS
ALTER TABLE users ENABLE ROW LEVEL SECURITY;
ALTER TABLE incidents ENABLE ROW LEVEL SECURITY;
ALTER TABLE security_events ENABLE ROW LEVEL SECURITY;

-- User Profile Policy
CREATE POLICY "Users can view and edit own profile"
  ON users FOR ALL
  USING (auth.uid() = id);

-- Incident Read Access
CREATE POLICY "Authenticated users can read incidents"
  ON incidents FOR SELECT
  TO authenticated
  USING (true);
```
